# Мобильный контур РКС (MytraGo)

## Цель
Полевой рабочий на дешёвом Android (BV6300) «включил и работает»:
сканирует QR для привязки, получает задания, заполняет отчёт, делает фото, отправляет.
Без настроек и ввода URL.

## Архитектура — одно приложение, две обёртки
Один SvelteKit-фронт (SPA, `adapter-static`) собирается в статику и работает в двух контекстах:

| Контекст | Запуск | Офлайн | Нативные возможности |
|---|---|---|---|
| Web-PWA (браузер) | прод (HTTP, VPN) / локальный IP | service worker | нет (getUserMedia — ненадёжно) |
| **Capacitor APK (основной)** | нативный WebView, ассеты из APK | локальная статика + офлайн-очередь | ML Kit (QR), Camera, Geolocation, Preferences |

**Основная цель — Capacitor APK.** Web-PWA оставлен как запасной/отладочный путь.

## Ключевые решения и почему
1. **QR-сканер — нативный `@capacitor-mlkit/barcode-scanning`** (не html5-qrcode):
   html5-qrcode (getUserMedia) давал чёрный экран на BV6300.
   ML Kit рисует камеру ПОД WebView: WebView делаем прозрачным, контент скрываем
   (`visibility: hidden`), оставляем только слой сканера `.barcode-scanner-modal`.
2. **QR содержит URL** `/m/enroll?code=XXXX` → при сканировании извлекаем `code`
   из URL (функция `extractCode`), а не шлём весь URL в бэк.
3. **Фото — нативный стоп-кадр из видеопотока** (CameraX, свой Kotlin-плагин),
   AVIF, 1600 px, EXIF-геометка + «юбка» с текстом (см. раздел «Фото»).
4. **Service worker — только web-PWA.** В Capacitor не регистрируется
   (`Capacitor.isNativePlatform()`). В самом SW API не кэшируется и не перехватывается:
   только `GET`, только same-origin, `/api/*` — мимо.
5. **Адрес бэка** — `VITE_API_URL` при сборке (прод: `http://10.10.102.214`, HTTP, через VPN;
   dev-тест на телефоне: локальный IP машины). Без HTTPS/туннеля.
   (`PUBLIC_API_URL` не инлайнится в rolldown-vite без `svelte.config.js` → используем `VITE_*`.)
6. **API-запросы — нативный `CapacitorHttp`** (OkHttp), а не `fetch`:
   `fetch` из WebView давал «Failed to fetch» (CORS/сетка WebView). Нативный HTTP
   идёт мимо WebView/CORS напрямую через нативный стек.
7. **Старые service worker'ы сносятся** при старте в Capacitor (`unregister` всех
   регистраций): SW от прошлых установок APK остаётся в WebView и мешает.

## Технические заметки
- Сборка APK: задать `VITE_API_URL` в `.env` → `bun run build` → `bunx cap sync android` →
  `gradlew assembleDebug` (JAVA_HOME = jdk21).
- APK называем с числовым префиксом: `00-…`, `01-…`, … (debug-сборки в Downloads).
- Эмулятор `Medium_Phone_API_37.0` — для проверки превью камеры
  (виртуальная камера, реальный QR на нём не проверить).
- Чёрный экран камеры на дешёвых устройствах = проблема getUserMedia; используем ML Kit.

## Совместное выполнение (несколько исполнителей)

Статус: реализовано (ядро). Сценарии:
1. Отдать N заданий в одном НП двум исполнителям — делят сами.
2. Один пришёл и не застал (недопуск), другой в другой день смог.

### Согласовано
- **Маркер недопуска:** в синк добавляем `last_result` + счётчик недопусков → мобилка показывает «уже был(и) N раз, недопуск».
- **Массовое назначение:** выбрать N строк → назначить M исполнителям разом (бэк: таблица `rks_task_assignees`).
- **Соисполнитель — не мульти-назначение, а поле мобильного отчёта.** Для работ «Допуск ПУ 3ф» и «Инструментальная проверка 3ф» исполнитель = бригада из 2 человек; второй человек выбирается основным исполнителем на своём устройстве (поле `co_executor` в отчёте).

### Семантика результата
- `успешно` — терминальное: задание «Выполнено», уходит со всех устройств.
- `недопуск` — НЕ терминальное: остаётся доступным другим; фиксируем «кто/когда недопустился».
- `не выполнено` — не терминальное.

### Гонка и авто-синхронизация
- Первый `успешно` побеждает; поздние отчёты отклоняются (без отката статуса).
- Авто-синк: периодический опрос `/api/m/1/sync` (напр. 60 сек) + локальные уведомления о значимых событиях (новое задание / снято / выполнено другим).
- Пуш (FCM) — отложить, начать с опроса.

### Риск (принят)
- Без сети в поле возможна напрасная работа (двое на один адрес). Машина не ломается; масштаб оценим в эксплуатации.

### Сделано
- Таблица `rks_task_assignees` + миграция.
- Массовое назначение N строк → M исполнителей (мультивыбор).
- Sync и guard отчёта по набору исполнителей.
- Маркер «уже был(и) N раз, недопуск» в синке + плашка в мобилке.

## Фото (видеопоток)

Статус: захват реализован; аплоад в Capacitor — остался (см. ниже).

- **Захват** — стоп-кадр из живого превью (CameraX, свой Kotlin-плагин `CameraStream`), не системная камера. Нативный оверлей-превью + кнопки «Отмена»/«Снять».
- **Формат** — JPEG (качество 86) + EXIF GPS. AVIF на Android кодировать нечем (нет публичного API), у WebP нет записи EXIF на Android — поэтому пока JPEG; AVIF/WebP вернём, если появится либа.
- **Размер** — 1600 px по длинной стороне (под обучение нейронки: распознавание показаний и типа ПУ).
- **Геометка** — EXIF GPS (lat/lng) в файле фото (координаты из JS-геолокации).
- **«Юбка»** — узкая оранжевая полоса внизу с белым текстом: дата/время · координаты · № задания · ЭО (код энергообъекта `energy_object_code`, добавлен в синк). Композит Canvas/Bitmap в том же Kotlin-плагине.
- **Осталось** — нативный аплоад фото на `/api/m/1/photos` (сейчас `fetch`+FormData в Capacitor не работает → фото уходит в офлайн-очередь IndexedDB). Вариант: аплоад в том же Kotlin-плагине (OkHttp, multipart) или `CapacitorHttp` с base64.

## Подключение мобилок (прод, VPN)

- Без HTTPS/Cloudflare-туннеля: APK ходит по HTTP (`CapacitorHttp` + cleartext).
- Прод-сервер: `http://10.10.102.214` (HTTP, Apache:80 → uvicorn 8000). Бэкофис по этому же адресу.
- Dev-тест на телефоне: `VITE_API_URL=http://<локальный-IP-ПК>:5174` (телефон в той же Wi-Fi).
- Мобилки заходят через VPN (full-tunnel): устройство технически оказывается в локалке, весь трафик через туннель.
- Сборка прод-APK: `VITE_API_URL=http://10.10.102.214`.
- **Cleartext разрешён** (`android:usesCleartextTraffic="true"` в манифесте) — JSON API ходит по HTTP через `CapacitorHttp` (нативный OkHttp, без mixed-content).
- **Фото (текущее)** — `fetch('/api/m/1/photos')` с относительным URL: в Capacitor не работает (относительный URL + mixed-content HTTPS→HTTP). Починится вместе с «Фото из видеопотока» (нативный аплоад в Kotlin-плагине).
- CORS для нативного HTTP не нужен (OkHttp ходит мимо WebView).
