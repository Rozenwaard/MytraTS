# План перехода на Svelte (черновик / оценка)

Статус: **идея, не начато**. Начинаем только после стабилизации текущего React-фронта.
Бэкенд (Litestar) **не трогаем** — он фреймворк-агностик (JSON API).

## Зачем
- В Svelte нет проблемы ремоунта/лишних ре-рендеров как в React (тонкая реактивность `$state`, нет VDOM).
- Меньше кода: шаблоны + реактивность вместо хуков/`memo`/`useCallback`.
- Быстрее и легче: нет VDOM, меньше бандл.
- Планируемые ввод данных прямо в ячейки таблицы и редизайн в Svelte делаются естественнее.

## Целевой стек
- **Svelte 5** (runes: `$state`, `$derived`, `$effect`) + **SvelteKit** (или Vite + Svelte).
- TanStack: `@tanstack/svelte-query` вместо `react-query`, `@tanstack/svelte-table` вместо `react-table` (или своя простая таблица); роутинг — SvelteKit (файловые роуты) вместо TanStack Router.
- **Tailwind v4 + DaisyUI 5** — CSS-only, переносятся без изменений.
- TypeScript (strict) — как сейчас.

## Шаги (инкрементально, НЕ big-bang)
1. Новый `frontend-svelte/` рядом со старым `frontend/`; старый продолжает работать до переключения.
2. Перенести `api/*.ts` (client.ts, main-afl.ts, fin-report.ts, auth) — это чистый `fetch`, копируется почти как есть.
3. Портировать страницы по роутам: логин → main-afl (Загрузка/Обзор/Список/Настройка) → Отчёты (финотчёт/премия) → дашборд.
4. Заменить хуки:
   - `useAuth` → Svelte store (`$state`/`$derived`, класс `AuthStore`);
   - `useMainAfl`/`useMainAflStats` → `createQuery` из `@tanstack/svelte-query`.
5. `DataTable` → своя Svelte-таблица (сортировка, пагинация, мультивыбор, ПКМ-копирование); ввод в ячейки делаем сразу (`input`/`contenteditable` + `on:input` → PATCH).
6. Интерактив на svelte-идиомах: дебаунс поиска, вкладки, прогресс загрузки, тосты.
7. Редизайн поверх DaisyUI: вынести токены, отполировать таблицу и формы.
8. Паритет-проверка (все фичи и фиксы как в React-версии) → переключение: заменить `frontend/` на `frontend-svelte/`, удалить старый React-код.
9. Удалить React-зависимости из `package.json`.

## Риски / заметки
- Роутинг: TanStack Router → SvelteKit — другая модель (файловые роуты), потребуется перекладка.
- Оценка усилий: недели, но бэкенд + api-клиент + DaisyUI + доменная логика переиспользуются; регрессий по бэку не будет (он не меняется).
- Начинать только после стабилизации текущего фронта (цена, финотчёт, поиск).
